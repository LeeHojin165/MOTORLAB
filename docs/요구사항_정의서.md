# 요구사항 정의서 — MOTORLAB

RAG 기반 자동차 지식 서비스 · AI 코어 프로젝트 2회차

## 1. 서비스 개요

MOTORLAB은 1886년 벤츠 파텐트 모토르바겐부터 2026년형 전기차까지 차량 200대의 제원·역사 질문에 **차량 메타데이터와 위키백과 문서를 근거로** 답하는 서비스입니다. 답변의 사실 문장마다 [근거 n]을 붙이고, 실제로 인용한 근거의 제목·출처 종류·원문 링크를 함께 보여 줍니다. 근거가 없으면 추측하지 않고 "제공된 문서에서 확인되지 않습니다"라고 답합니다.

## 2. 도메인 확정 — 선택 조건 충족 근거

| 조건 | 충족 근거 |
|---|---|
| **항목 메타데이터 약 100건 이상** | 차량 **200대** (`data/cars_source.json` → `data/cars_enriched.json`). 1886~2026년 · 제조사 52곳 · 9개국(한국 68, 독일 45, 미국 36, 일본 22 등) · 가솔린 130 / 전기 42 / 디젤 13 / 하이브리드 13 / 수소 2. 차량마다 이름·연도·제조사·국가·기준 트림·차종·동력원·엔진·변속기·구동·출력·토크·0–100km/h·최고속도·연비/주행거리·전장·전폭·전고·휠베이스·공차중량·서스펜션·승차감 |
| **항목마다 연결되는 외부 문서** | 한국어·영어 위키백과. 차량 자체 문서 묶음 345건(EN 200 · KO 145)을 모든 차량에 연결했고, 질문할 때마다 위키백과 API로 관련 문서를 추가 수집 |
| **출처와 이용 조건 기록** | 제원: 제조사 공개 자료·위키백과를 참고해 직접 정리 / 위키백과 본문: CC BY-SA 4.0(청크마다 원문 URL 저장, 화면에 원문 링크) / 사진: Wikimedia Commons(사진별 저작자·라이선스). 상세는 `data/SOURCES.md` |
| **근거 없이 답하면 틀리는 질문** | 아래 3절 |
| **판단이 위험한 도메인인가** | 아니오 — 차량 제원·역사 정보를 다루며 건강·금융 판단에 해당하지 않으므로 면책 안내는 두지 않음. 대신 "제원은 연식·트림·판매 시장에 따라 다를 수 있습니다"라는 안내를 입력창 아래와 화면 하단에 항상 표시하고, 답변에 기준 트림을 밝힘 |

## 3. 근거가 필요한 질문 (근거 없이 답하면 틀리기 쉬운 질문)

자동차 제원은 연식·트림·시장마다 다르고, 신형 차량은 학습 데이터에 없거나 이전 세대와 섞이기 쉽습니다. 실제 비교 결과는 `docs/RAG_전후_비교.md`에 있습니다.

| 질문 | 근거 없는 답 (gpt-4o) | 근거 값 |
|---|---|---|
| 2026 BMW iX3(노이어 클라쎄)의 최고출력과 배터리 용량은? | 약 286마력, 약 80 kWh | 345 kW(469 PS), 108.7 kWh |
| 2024 기아 EV3 롱레인지의 배터리 용량과 WLTP 주행거리는? | 약 77.4 kWh, 약 500 km | 81.4 kWh, 약 600 km |
| 2025 현대 아이오닉 9 퍼포먼스 AWD의 0-100km/h 가속은? | 약 3.5초 | 5.2초 |
| 1세대 테슬라 로드스터의 미국 출시 가격은? | 출처 없이 금액을 단정 | 색인 문서에 없음 → "확인되지 않습니다" |

## 4. 기능 요구사항

필수 기능은 정의서의 문장을 그대로 두고, 도메인 표현만 자동차에 맞게 바꿨습니다. 심화 기능은 4개 모두 선택했습니다.

| 번호 | 분류 | 요구사항명 | 요구사항 상세 (MOTORLAB 적용) | 우선순위 |
|---|---|---|---|---|
| F2001 | 데이터 | 항목 메타데이터 적재 | 차량 200대 목록을 로드하고, 차량 1대를 제원 전체가 들어간 하나의 색인 텍스트로 구성한다 | 필수 |
| F2002 | 색인 | 메타데이터 색인(RAG 1) | 차량 텍스트를 임베딩해 `car_meta` 컬렉션에 색인한다. 청크 ID = 차량 ID로 고정해 다시 색인해도 중복 저장되지 않는다 | 필수 |
| F2003 | 프롬프트 | 검색어 추출(프롬프트 1) | 자동차 전문 큐레이터 역할 프롬프트로 차량과 질문에서 위키백과 검색어를 JSON 배열로 추출한다. 차량 자체 문서는 항상 검색 대상에 포함한다 | 필수 |
| F2004 | 수집 | 외부 문서 수집(프롬프트 2) | 위키백과에서 후보를 모으고, 본문을 받기 전에 제목·요약만 보고 프롬프트 2로 색인할 문서를 고른 뒤 본문과 원문 URL을 수집한다. 이미 받은 질문·이미 수집한 검색어는 다시 수집하지 않는다. 외부 호출이 막히면 문서 묶음으로 대신한다 | 필수 |
| F2005 | 색인 | 외부 문서 색인(RAG 2) | 수집 문서를 청킹해 `car_docs` 컬렉션에 색인한다. 청크 크기·중복 길이는 `.env`로 조정하고, 청크 ID는 `{차량 ID}:{문서 ID}:{순번}` | 필수 |
| F2006 | 검색 | 근거 검색 및 병합 | 선택 차량의 메타데이터 청크를 항상 [근거 1]로 넣고, `car_docs`를 차량 ID로 좁혀 검색한 결과와 병합·중복 제거한다. Top-k는 `.env`와 화면 설정으로 조정한다 | 필수 |
| F2007 | 생성 | 근거 기반 답변 생성(프롬프트 3) | LangGraph retrieve → generate 두 노드. 검색된 근거만 사용하고, 근거가 없으면 "제공된 문서에서 확인되지 않습니다"라고 답한다. 근거마다 출처 종류(메타데이터/위키백과)를 붙인다 | 필수 |
| F2008 | 생성 | 근거 표시 | 답변 본문의 [근거 n]을 찾아 실제로 인용된 근거만 제목·출처 종류·원문 링크와 함께 표시하고, 인용 근거가 없으면 그 사실을 안내한다 | 필수 |
| F2009 | UI | 항목 선택 및 질의응답 | 차량 목록에서 차량을 고르고 채팅으로 질문한다. 대화 기록은 차량별로 따로 유지한다 | 필수 |
| F2010 | 서비스 | 도메인 특화 기능 | **제원 비교**(2~3대 메타데이터를 근거로 차이 요약)와 **사실 확인**(주장을 문서 근거로 사실/사실 아님/확인 불가 판정). 둘 다 근거를 함께 제시 | 필수 |
| F2011 | 서비스 | 조건 기반 항목 탐색 | "1990년 이전 후륜구동 수동 차"처럼 자연어 조건을 입력하면 메타데이터 색인 후보 20대 중 조건을 모두 만족하는 차량만 카드로 제시하고, 카드를 누르면 그 차량 대화로 이어진다 | 필수 |
| F2012 | UI | 진행 상태 및 안내 | 검색어 추출 → 후보 선별 → 수집·색인 → 근거 검색 → 답변 생성 5단계를 실시간으로 표시하고, 색인 없음·API 키 누락·외부 오류를 각각 안내한다 (위험 도메인 면책은 해당 없음) | 필수 |
| F2013 | UI | 프론트엔드 직접 구현 | HTML·CSS·JavaScript(프레임워크 없음) 화면과 FastAPI 서버를 분리하고, 요청·응답 형식을 정의한다(SSE 스트리밍) | 심화 |
| F2014 | 검색 | MMR 검색 적용 | 후보 `MMR_FETCH_K`(기본 20, 최소 Top-k×3)건을 가져와 다양성 기준으로 Top-k를 고른다. 화면에서 유사도 ↔ MMR 전환 | 심화 |
| F2015 | 품질 | RAG 전후 품질 비교 | 같은 질문을 RAG 없이/근거를 붙여 답하게 해 나란히 표시하고, 대표 질문 7개의 비교를 문서로 정리한다 | 심화 |
| F2016 | 수집 | 여러 문서 출처 결합 | 위키백과(KO·EN)와 PDF(`data/pdfs/{차량 ID}/*.pdf`, 쪽 단위 분할)를 같은 컬렉션에 색인하고 근거에 출처 종류를 구분해 표시한다 | 심화 |

## 5. 비기능 요구사항

| 번호 | 분류 | 요구사항명 | 요구사항 상세 (MOTORLAB 적용) |
|---|---|---|---|
| NF2001 | 성능 | 응답 시간 | 수집이 필요 없는 질문은 수 초, 새 문서를 수집하는 첫 질문도 진행 상태를 보며 기다릴 수 있는 수준(약 15~35초). 같은 질문의 두 번째부터는 수집을 생략한다 |
| NF2002 | 성능 | 수집 캐시 | `data/collect_cache.json`에 (차량, 질문) → 검색어, (차량, 검색어) → 선별·제외 문서를 기록해 다시 수집하지 않는다 |
| NF2003 | 보안 | API 키 관리 | 키는 `.env`(환경변수)에만 두고 `.gitignore`에 포함한다. 코드·문서·로그에 키를 쓰지 않는다 |
| NF2004 | 보안 | 내부 정보 비노출 | 화면에는 오류 코드별 고정 문구만 보내고, 추적 정보는 서버 로그에만 남긴다. 근거는 160자 발췌만 보내고 프롬프트는 응답에 넣지 않는다 |
| NF2005 | 확장성 | 모듈 분리 | 수집(`collect`)·색인(`store`)·검색·생성(`rag`)·서비스(`services`)·API(`server.py`)·UI(`frontend`)를 분리하고, 도메인에 묶인 데이터·프롬프트는 `backend/domain`에 모은다 |
| NF2006 | 품질 | 외부 API 예절 | 위키백과 요청 간격 1초 이상, 429·5xx 재시도(`Retry-After` 우선), User-Agent에 연락처 포함 |
| NF2007 | 법·윤리 | 출처와 이용 조건 | 데이터·문서·사진의 출처와 라이선스를 README와 `data/SOURCES.md`에 기록하고, 화면에 원문 링크와 사진 저작자를 표시한다 |
